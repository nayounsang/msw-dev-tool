# Node CLI

`@msw-dev-tool/node-cli` gives AI agents and scripts machine-readable JSON control of a Node MSW Dev Tool session. Use it to select HTTP and WebSocket scenarios in a process that runs `setupDevToolServer()`.

## Configuration

### Install

<Tabs items={["pnpm", "npm", "yarn"]}>
  <Tabs.Tab>
  ```bash copy
  pnpm add -D @msw-dev-tool/core @msw-dev-tool/node-cli msw
  ```
  </Tabs.Tab>
  <Tabs.Tab>

  </Tabs.Tab>

### Connect the runtime

```ts copy
import { setupDevToolServer } from "@msw-dev-tool/core/node";
import { handlers } from "./handlers";

const server = await setupDevToolServer(...handlers);
server.listen();
```

Each server process writes a PID-named session snapshot to `.msw-dev-tool/sessions/<pid>.json` in its current working directory. List sessions, then use `--pid` whenever more than one is available.

```bash copy
msw-dev-tool sessions
msw-dev-tool --pid 4182 session
```

<Callout type="warning">
After changing handler code, run `msw-dev-tool --pid 4182 reset` and wait for its JSON result before issuing another command. A normal process exit removes its session file; inspect and remove stale files after a crash before selecting a PID.
</Callout>

## Commands & API

Every command prints machine-readable JSON to stdout. Handler IDs are JSON strings such as `{"path":"/api/items","method":"get"}`; use `list` to copy them safely.

### HTTP scenarios

```bash copy
msw-dev-tool --pid 4182 list
msw-dev-tool --pid 4182 get '{"path":"/api/items","method":"get"}'
msw-dev-tool --pid 4182 set-behavior '{"path":"/api/items","method":"get"}' delay
msw-dev-tool --pid 4182 set-custom-response '{"path":"/api/items","method":"get"}' --json '{"status":200,"body":"[]"}'
msw-dev-tool --pid 4182 set-behavior '{"path":"/api/items","method":"get"}' 'custom response'
msw-dev-tool --pid 4182 add-temp --json '{"path":"/api/preview","method":"get","contentType":"application/json","status":"200","response":"{\\"ok\\":true}"}'
msw-dev-tool --pid 4182 remove-temp '{"path":"/api/preview","method":"get"}'
msw-dev-tool --pid 4182 reset
```

```json
{"ok":true,"handlers":[{"id":"{\\"path\\":\\"/api/items\\",\\"method\\":\\"get\\"}","path":"/api/items","method":"get","behavior":"default"}]}
```

### WebSocket scenarios

First discover endpoint and listener IDs, then pass the selected ID to a mutation command.

```bash copy
msw-dev-tool --pid 4182 ws-list
msw-dev-tool --pid 4182 ws-get-endpoint 'websocket:endpoint:ws://localhost:8080/chat'
msw-dev-tool --pid 4182 ws-add-endpoint --json '{"kind":"string","value":"ws://localhost:8080/preview"}'
msw-dev-tool --pid 4182 ws-set-endpoint-enabled 'websocket:endpoint:ws://localhost:8080/chat' false
msw-dev-tool --pid 4182 ws-add-listener 'websocket:endpoint:ws://localhost:8080/preview:0' --json '{"preset":"send","options":{"message":"hello"}}'
msw-dev-tool --pid 4182 ws-set-listener-behavior '<listener-id>' --json '{"preset":"close","options":{"code":4001,"reason":"test"}}'
msw-dev-tool --pid 4182 ws-set-listener-custom-response '<listener-id>' --json '{"type":"send","dataType":"string","value":"hello"}'
msw-dev-tool --pid 4182 ws-set-listener-enabled '<listener-id>' false
msw-dev-tool --pid 4182 ws-remove-listener '<temporary-listener-id>'
msw-dev-tool --pid 4182 ws-remove-endpoint 'websocket:endpoint:ws://localhost:8080/preview:0'
```

```json
{"ok":true,"endpoint":{"endpointId":"websocket:endpoint:ws://localhost:8080/chat","enabled":false,"listeners":[]}}
```

`ws-add-endpoint`, `ws-add-listener`, and `ws-set-listener-behavior` accept their matcher or behavior through `--json`. Save custom response data with `ws-set-listener-custom-response`, then select `{ "preset": "custom response" }`. Send supports String, Blob, and ArrayBuffer values; Blob and ArrayBuffer values are space-separated hexadecimal bytes. Close accepts optional `code` and `reason`. Code-discovered endpoints and listeners cannot be removed; remove commands apply only to temporary items.
