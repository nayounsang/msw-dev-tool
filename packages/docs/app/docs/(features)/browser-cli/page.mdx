# Browser CLI

`@msw-dev-tool/browser-cli` lets an AI agent or script control HTTP and WebSocket scenarios in a browser MSW Dev Tool session through Chrome DevTools Protocol (CDP). Set a scenario with the CLI, inspect the same target through CDP, and verify the user-visible result.

## Configuration

### Install and connect the runtime

```bash copy
pnpm add -D @msw-dev-tool/browser-cli @msw-dev-tool/core msw
```

The target tab must run `setupDevToolWorker(...handlers)`. Start a separate Chrome profile with remote debugging enabled:

<Tabs items={["macOS", "Windows", "Linux"]}>
  <Tabs.Tab>
  ```bash copy
  open -na "Google Chrome" --args --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir=/private/tmp/chrome-debug-9222
  ```
  </Tabs.Tab>
  <Tabs.Tab>
  ```powershell copy
  & "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir="$env:TEMP\chrome-debug-9222"
  ```
  </Tabs.Tab>
  <Tabs.Tab>
  ```bash copy
  google-chrome --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-debug-9222
  ```
  </Tabs.Tab>
</Tabs>

### Choose a target

List browser page targets and select the tab that has initialized `setupDevToolWorker()`. `sessionStorage` is tab-scoped, so every mutation requires that target ID.

```bash copy
msw-dev-tool-browser tabs --cdp-url http://127.0.0.1:9222
msw-dev-tool-browser session --cdp-url http://127.0.0.1:9222 --target <target-id>
```

<Callout type="warning">
The remote-debugging endpoint gives local processes browser-debugging access. Keep the separate Chrome profile running and do not use a regular browsing profile.
</Callout>

## Commands & API

All commands print machine-readable JSON. Replace `<cdp>` with `--cdp-url http://127.0.0.1:9222 --target <target-id>` in the examples below.

### HTTP scenarios

```bash copy
msw-dev-tool-browser list <cdp>
msw-dev-tool-browser get '{"path":"/api/items","method":"get"}' <cdp>
msw-dev-tool-browser set-behavior '{"path":"/api/items","method":"get"}' delay <cdp>
msw-dev-tool-browser set-custom-response '{"path":"/api/items","method":"get"}' --json '{"status":200,"body":"[]"}' <cdp>
msw-dev-tool-browser set-behavior '{"path":"/api/items","method":"get"}' 'custom response' <cdp>
msw-dev-tool-browser add-temp --json '{"path":"/api/preview","method":"get","contentType":"application/json","status":"200","response":"{\\"ok\\":true}"}' <cdp>
msw-dev-tool-browser remove-temp '{"path":"/api/preview","method":"get"}' <cdp>
msw-dev-tool-browser reset <cdp>
```

```json
{"ok":true,"handlers":[{"id":"{\\"path\\":\\"/api/items\\",\\"method\\":\\"get\\"}","path":"/api/items","method":"get","behavior":"default"}]}
```

### WebSocket scenarios

```bash copy
msw-dev-tool-browser ws-list <cdp>
msw-dev-tool-browser ws-get-endpoint 'websocket:endpoint:ws://localhost:8080/chat' <cdp>
msw-dev-tool-browser ws-add-endpoint --json '{"kind":"string","value":"ws://localhost:8080/preview"}' <cdp>
msw-dev-tool-browser ws-set-endpoint-enabled 'websocket:endpoint:ws://localhost:8080/chat' false <cdp>
msw-dev-tool-browser ws-add-listener 'websocket:endpoint:ws://localhost:8080/preview:0' --json '{"preset":"send","options":{"message":"hello"}}' <cdp>
msw-dev-tool-browser ws-set-listener-behavior '<listener-id>' --json '{"preset":"close"}' <cdp>
msw-dev-tool-browser ws-set-listener-custom-response '<listener-id>' --json '{"type":"send","dataType":"Blob","value":"68 69","metadata":{"type":"text/plain"}}' <cdp>
msw-dev-tool-browser ws-set-listener-behavior '<listener-id>' --json '{"preset":"custom response"}' <cdp>
msw-dev-tool-browser ws-set-listener-enabled '<listener-id>' false <cdp>
msw-dev-tool-browser ws-remove-listener '<temporary-listener-id>' <cdp>
msw-dev-tool-browser ws-remove-endpoint 'websocket:endpoint:ws://localhost:8080/preview:0' <cdp>
```

```json
{"ok":true,"endpoint":{"endpointId":"websocket:endpoint:ws://localhost:8080/chat","enabled":false,"listeners":[]}}
```

`ws-add-endpoint`, `ws-add-listener`, and `ws-set-listener-behavior` use `--json` input. Use `ws-set-listener-custom-response` to save a response, then select `{ "preset": "custom response" }` with `ws-set-listener-behavior`. Send responses use `dataType: "string"`, `"Blob"`, or `"ArrayBuffer"`; binary values are space-separated hexadecimal bytes. Close responses accept optional `code` and `reason`. Browser changes apply immediately to the in-memory store and persist to the selected tab's `sessionStorage`; refresh only to confirm persistence. Code-discovered WebSocket endpoints and listeners cannot be deleted, while temporary ones can.
